# LF-05: Refuse overlapping requests

**Status:** Ready
**Sprint:** 1
**Type:** Story
**Labels:** gap:functional, gap-register:GAP-F3

## Description

As an employee, I want the system to refuse a leave request that overlaps an
existing non-cancelled request of mine, so that I cannot double-book and create
a reconciliation mess for HR.

The seed data contains a live example. Priya Raman has two pending requests:
20 to 24 July 2026 and 22 to 28 July 2026. Both were accepted.

## Acceptance criteria

- **Given** an approved request from 20 to 24 July 2026
  **When** I submit a request from 22 to 28 July 2026
  **Then** I receive a 409 with a message naming the conflicting dates

- **Given** a cancelled request over 20 to 24 July 2026
  **When** I submit a request from 22 to 28 July 2026
  **Then** the request is created with status Pending

- **Given** a pending request over 20 to 24 July 2026
  **When** I submit a request from 22 to 28 July 2026
  **Then** I receive a 409

- **Given** an employee with no requests
  **When** they submit any date range
  **Then** the request is created normally

## Out of scope

- Partial-day overlap
- Overlap against another employee's leave (team capacity is not modelled)
- Retroactive cleanup of the existing overlapping rows in the seed data

## Constraints

- The check belongs in `src/app/api/requests/route.ts`, at the POST handler
- The predicate belongs in `src/lib/leave.ts` so it can be unit tested
- Existing tests must stay green. Add tests for all four criteria
- Do not modify `prisma/schema.prisma`. This is an application-level rule
